# **Тензоры**
==**Тензоры**== - это массивы (похож на массивы из NumPy), делящиеся на типы:

-  **0-мерный** - *это в аналогии 0d (точка) - то есть массив состоящий из одного числа/скаляр, пример: 3; 4; 12 312. (все они не зависимы от друга)*
	  `torch.tensor(5)`
- **1-мерный** - *это как 1d (абсцисс / ось x) - то есть массив состоящий из чисел, которые идут слева на право, вектор (аналог простого списка в Py), пример:* [1, 2, 3, 11].
-  **2-мерный** - *это как 2d  (абсцисс и ординат / ось x и y) - то есть массив состоящий из чисел, которые аналогична таблице из строк и столбцов (матрица), пример:* 
   $\begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}$
```Python
   [
   [ 1, 3, 5 ], 
   [ 23, 13, 44 ],
   [ 32, 22, 11 ]
   ]
```
   [ [ 1,2 ] [ 3, 4 ] ]
- **3-мерный** - *это как 3d (ось x, y и z) - то есть массив состоящий из чисел, как бы это массив в массиве в массиве*: 
   
   [ [ [ числа 1 мерный массив ], [ числа 1 мерный массив  ] ], 
   [ [ числа 1 мерный массив ], [ числа 1 мерный массив ] ] ] 
   
   *пример:*
```Python
    tensor_3d = torch.tensor ([
    [
        [3, 3, 3], 
        [4, 4, 4]
    ],
    [
        [4, 6, 7], 
        [34, 124, 4]
    ]
 ])
```
-  **4-мерный тензор (4D)** - *можно представить как линию, состоящую из 3D-кубиков. Хорошая аналогия - это обычная книжная полка, на которой в один ряд стоят "трехмерные" книги.*
    Чтобы найти конкретное число в таком массиве, понадобятся четыре координаты:
    [номер книги на полке, страница в этой книге, строка на странице, список из символов (слово)]. 
		слово здесь как векторный массив => привет = [п, р, и, в, е, т]
		то есть список из символов
	
    В сфере искусственного интеллекта 4D-тензоры используются постоянно, например, для передачи пакета (батча) из нескольких цветных картинок в нейросеть.
	пример обычного 4-ох мерного тезора: [ [ [ [1, 2, 3 ] ], [ [5, 6, 7] ], [ [2, 4, 6] ] ] ] ] -> его размер (1, 3, 1, 3)

```Python
print(mytensor)
```
**Вывод:**
```

         [[1., 1., 1.]],

         [[1., 1., 1.]]]])
```
	
	
- **5-мерный тензор (5D)** - *это уже целая плоская таблица, состоящая из 3D-кубиков. В жизни это напоминает большой книжный шкаф, где книги распределены не в один ряд, а стоят на разных полках (высота) и в разных секциях (ширина).*
	 Здесь для поиска нужного элемента требуется пять координат: 
	 [номер полки, номер книги на этой полке, страница, список из символов].
	 
	В искусственном интеллекте в виде 5D-тензоров обычно хранятся пакеты видеороликов, где осями выступают количество видео, кадры во времени, цвет, высота и ширина кадра.

- **6-мерный тензор (6D)** *представляет собой огромный трехмерный супер-куб, собранный из маленьких 3D-кубиков. Ближайшая аналогия из реального мира - это целая библиотека со множеством комнат и шкафов.*
	 В данном случае система координат разрастается до шести значений: 
	 [номер ряда шкафов, номер конкретного шкафа в этом ряду, номер полки, номер книги, страница, список из символов]

## **Инициализация тензоров**
==torch.Tensor== - это конструктор класса, выделяет память под тензор, но использует остаточные значения, которые уже были в памяти (если ничего не передать).

> Если передавать в них списки, то Tensor их всегда сделает float, а tensor преобразует в нужный тип.

==torch.tensor== -статик метод, передается конкретный список, и сам определяет тип данных.

`torch.tensor(data, dtype=..., device=..., requires_grad=..., pin_memory=...)`

`x = torch.tensor([1, 2, 3], dtype=torch.int32)`
**dtype** - *не обязательный параметр, через который можно сменить тип данных.*

#### **Типы данных для dtype:**
`signed` (со знаком)
`unsigned` (без знака)
###### Целые числа (Integers)

**`char`** (8-bit) — `torch.int8` (со знаком -) (без знака  u от -128 до 127)

**`unsigned char`** (8-bit) — `torch.uint8`  без отрицательных чисел (от 0 до 255)

**`short`** (16-bit) — `torch.int16`

**`int`** (32-bit) — `torch.int32`

**`long`** (64-bit) — `torch.int64` (стандартный тип для индексов в PyTorch)


###### Числа с плавающей точкой (Floating point)

**`half` / `float16`** (16-bit) — `torch.float16` (используется для ускорения вычислений на GPU)

**`bfloat16`** (16-bit brain float) — `torch.bfloat16` (стандарт для обучения современных нейросетей)

**`float` / `single`** (32-bit) — `torch.float32` ( стандартный  «золотой» тип для обучения)

**`double`** (64-bit) — `torch.float64`
#### **device=..?**
**`device` (устройство)** - *это указание для PyTorch, в какой именно памяти компьютера должен "жить" тензор и где физически будут происходить математические вычисления с ним.*
`device = 'cpu'` - проц.
`device = 'cuda'` - видеокарта 
`device = 'mps'` - (для Apple Silicon M1/M2/M3)

**!при операциях, тензоры должны находиться на 1 устройстве!**

```Python

# можно как y = y.cuda()  
print(x + y) # ОШИБКА, тензор на видюхе
```

#### **requires_grad=...?**
**`requires_grad` (требует градиент)** - *это тумблер-переключатель (True или False), который приказывает PyTorch включить камеру видеонаблюдения за конкретным тензором.*

#### **Умножение**
###### **Матричное умножение**

**`torch.matmul`** (сокращение от *matrix multiplication*) - *функция, которая выполняет матричное умножение 2-ух тензоров.*
`@` - *используют чаще этот знак.*

`torch.matmul(a, b):`
**a - первая матрица(левый операнд), b - вторая матрица (правый операнд)**

***Секретный параметр `out`:***  на самом деле он не какой не секретный, просто его редко используют. **Out** - *это необязательный третий параметр* ( `torch.matmul(a, b, out)` ) *он присваивает тензору результат **Матричного умножения.** Тензор к которому мы хотим присвоить результат должен быть создан, должен иметь идеальный итоговый размер* (`torch.matmul(a, b, out=result_tensor)` - где `a` и `b` операнды, a result_tensor, заранее созданный пустой тензор, идеальных размеров). *Когда мы передаем* `out`, *то мы обязательно должны явно указывать имя этого параметра.* (В реальном коде `out` используют для оптимизации, когда борются за каждую миллисекунду скорости работы нейросети. Когда мы присваиваем результат в переменную ( `С = torch.matmul(A, B)` ), так требуется больше памяти, больше времени (для выделения памяти)).
###### Правила

> [! ] 1. Главное правило размерностей (Совместимость)
> 
> 
> Чтобы матрицы $A$ и $B$ можно было перемножить ($A @ B$), **количество столбцов первой матрицы должно быть строго равно количеству строк второй**.
> 
> - Размер матрицы $A$: $[M \times \mathbf{N}]$
>     
> - Размер матрицы $B$: $[\mathbf{N} \times K]$
>     
> 
>   
>   **Размер результата: $[M \times K]$**
>     
> 
> > Внутренние индексы должно совпадать ($N = N$), а внешние ($M$ и $K$) задают итоговый размер.


пример ситуации:
```Python
a = torch.tensor([[1, 2, 3], [3, 3, 3]])  
b = torch.tensor([[1, 2, 3], [2, 1, 2]])  
c = a @ b  
print(c)
```
В такой ситуации выведет ошибку: 
```
Traceback (most recent call last):
  File "D:\Python\PythonPyTorch\main.py", line 16, in <module>
    c = a @ b
        ~~^~~
RuntimeError: mat1 and mat2 shapes cannot be multiplied (2x3 and 2x3)
```

Тензор `a` имеет размерность (2 *:`M`*, 3 *:`N`*), тензор `b` имеет размерность (2 *:`N`*, 3 *:`K`*), где

## Функции активации

==**Функции активации**== - это математический компонент искусственного нейрона, который определяет, передавать ли полученный сигнал дальше по сети.
Нужна она по одной важнейшей причине:
- нелинейность - ибо без нее это обычная прямая, одна из причин почему после [[Перцептрон |перцептрона]] было затишье, это тупо невозможность решить XOR задачи и т.п. 
###### 1. Когда нужно строго от 0 до 1 (Меньше или равно 1) — `Sigmoid`

Она сжимает любое число (хоть $-9999$, хоть $+9999$) в диапазон **от 0 до 1**.

- **Зачем:** Идеально подходит для финального слоя, когда сеть должна выдать вероятность. Например: _"С вероятностью 0.87 (87%) на этой картинке кот"_.
    
###### 2. Когда нужно от -1 до 1 - `Tanh` (Гиперболический тангенс)

Похожа на сигмоиду, но сжимает данные в диапазон **от -1 до 1**.

- **Зачем:** Часто используется во внутренних слоях, потому что когда среднее значение выходов близко к нулю, нейросеть обучается быстрее и стабильнее.
    
###### 3. Когда значение может быть ГОРАЗДО БОЛЬШЕ 1 - `ReLU`

Это самая популярная функция активации в современных нейросетях. Её логика гениально проста: если на вход пришло отрицательное число, она превращает его в $0$. Если пришло положительное — она **пропускает его как есть, вообще не изменяя**.
- **Значение:** Если нейрону пришло число $150$, на выходе будет $150$ (что намного больше 1).
    
- **Зачем:** Она работает невероятно быстро (компьютеру не нужно считать сложные экспоненты, как в сигмоиде) и решает проблему «затухания градиентов», из-за которой глубокие сети раньше не могли обучаться.
###### 4. Когда сумма всех выходов должна быть строго равна 1 — `Softmax`

Применяется на самом последнем слое в задачах мультиклассификации (когда нужно выбрать один вариант из нескольких, например: это собака, кошка или попугай?). Она превращает выходы в набор вероятностей, которые в сумме дают ровно **1.0 (100%)**
###### 5. `nn.GELU()` -Gaussian Error Linear Unit 
`nn.GELU()` - это нелинейная функция активации, которая масштабирует входное значение в зависимости от того, насколько оно больше других значений в вероятностном распределении (используется функция ошибок Гаусса).

Она довольно сложная, так как завязана на теорию вероятностей и кумулятивное нормальное распределение (функцию Гаусса):

$$f(x) = x \cdot \Phi(x)$$

_Где $\Phi(x)$ - это вероятность того, что стандартная случайная величина меньше $x$._ На практике компьютер считает её через аппроксимацию (приближенную формулу), простыми словами, $\Phi(x)$ возвращает вероятность (число от 0 до 1). Чем больше $x$, тем ближе к 1:

$$f(x) \approx 0.5x \cdot \left(1 + \tanh\left(\sqrt{\frac{2}{\pi}} \cdot (x + 0.044715x^3)\right)\right)$$
**В чем суть:** В отличие от ReLU, график GELU идеально гладкий.

- При больших положительных $x$ она работает как ReLU (пропускает число).
    
- При больших отрицательных $x$ она плавно зануляется.
    
- **В районе нуля (от -2 до 0) она образует плавную ямку.** Если на вход пришло `-0.5`, GELU не превратит его в жесткий ноль. Она позволит небольшому отрицательному сигналу пройти дальше.
#### **`ReLU`**
`ReLu` - *функция активации, которая пропускает положительные числа (без изменений), но когда отрицательные числа или 0, то превращает эти числа в `0`.*
-33 => 0
1 => 1
0 => 0

#### nn.Linear
`nn.Linear` (Линейный или полносвязный слой) - *это математический оператор, осуществляющий **аффинное преобразование** над входным тензором. Он отображает вектор из исходного конечномерного векторного пространства $\mathbb{R}^N$ в новое векторное пространство $\mathbb{R}^M$.*

`nn.Linear` (Линейный / Полносвязный слой)
**Что делает:** Изменяет размерность данных (переводит вектор из $N$ чисел в вектор из $M$ чисел). Например: `nn.Linear(2, 3)` берет 2 числа на входе и выдает 3 на выходе.

**Как устроен:** Каждый вход соединен с каждым выходом через персональный «множитель».

**Формула:** $Y = X \cdot W + b$

- **$W$ (Веса):** Поворачивают и масштабируют пространство.

- **$b$ (Смещение / Bias):** Сдвигает график в сторону (чтобы линия разделения не была привязана к центру координат $(0,0)$).

**Главное ограничение:** *Умеет делать только прямые линии или плоские поверхности. Он геометрически «слеп» к сложным изгибам. Чтобы сеть могла решать нелинейные задачи (вроде XOR), сразу после `nn.Linear` обязательно нужно вызывать функцию активации (например, `F.relu`).*

#### `model.train()` и `model.eval()`
`model.train()` - переводит модель в режим обучения. Ничего не принимает и возвращает сам объект модели. Сообщает некоторым слоям "*сейчас идет обучение*", большинство слоев никак не реагируют на это (`Linear`, `ReLU` и т.п.) для них ничего не меняется, но есть специальные слои:
##### Dropout:
`nn.Dropout(p=?)` - это слой регуляризации, который во время обучения случайно отключает часть нейронов(c вероятностью `p`), чтобы уменьшить переобучение (overfitting).
	 [о переобучение](https://habr.com/ru/companies/otus/articles/860958/)

Допустим, есть выход слоя:

```
[0.8, 1.2, 0.5, 2.1]
```
Если:
```
nn.Dropout(p=0.5)
```
то примерно половина элементов будет занулена:
```
[0.8, 0.0, 0.5, 0.0]
```
или
```
[0.0, 1.2, 0.0, 2.1]
```
*Случайный выбор происходит на каждом проходе.*
  А смысл этого, чтобы каждый нейрон не зависел от другого слишком сильно:
  *нейрон A всегда (очень) помогает нейрону B* - из за этого сеть начинает запоминать данные, вместо обучения предугадывать (закономерностям).
  пример:
  `drop = nn.Dropout(p=0.3)` 
  это значит 30% нейронов отключены (аннулированы), а 70% работают.
##### BatchNorm

*более конкретно* 
**Batch Normalization (BatchNorm)** — слой нормализации, который приводит активации нейронов к более стабильному распределению внутри батча, ускоряя и стабилизируя обучение нейронной сети.

### Dataset

`Dataset` *отвечает за **доступ к единичному элементу** данных. Это абстракция над физическим хранилищем (файлом, массивом).*
каждый раз при создание датасета, нужно переопределить 3 метода!
это:
==**`__init__`**== - *дефолт конструктор (создание заготовки).* Тут мы должны передать пути, либо ссылку на них (или ссылку на массив с данными), или CSV-таблицу со ссылками на картинки и правильными ответами (например). В целом этот шаг называется: **Подготовка и логика загрузки.**

`__init__(self, ...)`

**Важно:** Мы НЕ загружаем здесь сами тяжелые картинки или тексты в память! Мы лишь сохраняем "карту" (массив путей или таблицу), по которой будем их искать.
``` Python
def __init__(self, data_path, transforms=None):
    # Сохраняем пути или загружаем легкую CSV-таблицу
    self.df = pd.read_csv(data_path) 
    # Сохраняем функции трансформации данных (например, изменение размера картинок)
    self.transforms = transforms
```
--- 
==**`__len__`**== - *измеритель (сколько всего данных).* Самый простой метод:D (**Длина датасета**), он должен возвращать одно целое число - общее количество элементов в датасете. Это нужно для `DataLoader`, чтобы он знал, когда заканчивается эпоха обучения. 

`__len__(self)`

```Python
def __len__(self):
    # Просто возвращаем длину нашей таблицы или массива путей
    return len(self.df)
```
--- 
==**`__getitem__`**== - *Доставщик (дай мне элемент под номером X).* Сюда прилетает индекс `idx` (например, число 42). Задача - пойти по этому индексу в свои сохраненные данные, достать конкретную строку/файл, обработать и вернуть пару: **(Признаки, Таргет)** то есть `(X, y)`. Этот шаг назовём, как: **выдача одного элемента.**

```Python
def __getitem__(self, idx):
    # 1. Находим путь к файлу или строку по индексу
    img_path = self.df.iloc[idx]['image_path']
    label = self.df.iloc[idx]['label']
    
    # 2. Считываем тяжелый файл с диска СТРОГО в момент запроса
    image = cv2.imread(img_path) 
    
    # 3. Применяем трансформации (если они есть)
    if self.transforms:
        image = self.transforms(image)
        
    # 4. Возвращаем готовый кортеж (фичи, метка)
    return image, label
```

#### `DataLoader` 

`DataLoader` *отвечает за **стратегию подачи данных** в модель. Он автоматизирует батчевание, перемешивание и многопоточную фоновую загрузку, избавляя программиста от написания сложных циклов и работы с потоками.*
Не нужно писать новый класс, использовать созданием объекта:
`data_loader = data.DataLoader(dataset, batch_size=8, shuffle=True)`

- `batch_size`: Сколько примеров склеить в одну пачку (батч) для видеокарты. В примере: $8$

- `shuffle=True`: Перемешивать данные каждый круг обучения (эпоху). **Критически важно для обучения**, иначе сеть запомнит порядок ответов.

- `num_workers`: Сколько параллельных процессов процессора будут загружать данные. Для маленьких данных (как этот XOR) всегда ставим `0`. Для тяжелых картинок ставим `4` или больше.

- `drop_last=True`: Если 203 картинки, а `batch_size=10`, то в конце останется «хвостик» из 3 картинок. Этот флаг просто выкидывает этот неполный хвостик, чтобы размер батчей всегда был одинаковым.

$\hat{y}_i$ - это предсказание сети 
$y_i$ - это правильный ответ 
это все функции потер в Pytorch, но для себя я выделю парочку:

### 1. `nn.MSELoss`
**Для:** регрессии.

Когда нужно предсказывать число:
- Цена квартиры
- Температура
- Возраст
- Координаты объекта
***Формула:***

$$
L = \frac{1}{N}\sum_{i=1}^{N}(y_i - \hat{y}_i)^2
$$
---
Пример:

``` Python
pred = torch.tensor([4.0])
target = torch.tensor([5.0])
```
---
Ошибка:
```
(5 - 4)^2 = 1
```
**Принцип:** *большие ошибки штрафуются сильнее.*
Ошибка:

$1 → 1² = 1$
$2 → 2² = 4$
$10 → 10² = 100$

Поэтому сеть старается избавиться от крупных промахов.

### 2. `nn.L1Loss`
**Для:** регрессии.

***Формула***
$$
L = \frac{1}{N}\sum_{i=1}^{N}|y_i - \hat{y}_i|
$$

---
**Принцип**
Штраф линейный.

```
Ошибка = 1  → 1
Ошибка = 2  → 2
Ошибка = 10 → 10
```
Менее чувствительна к выбросам, чем MSE.
### 3. `nn.CrossEntropyLoss`

**Для:** многоклассовой классификации.
Используется в:
> MNIST
> CIFAR
> ImageNet
> BERT
> GPT
> LLM

***Формула:***

$$
L = -\sum_{c=1}^{C} y_c \log(p_c)
$$

где:
$y_c$  — истинный класс (one-hot)
$p_c$  — вероятность класса после Softmax
 Что делает внутри

```
Softmax
+
NLLLoss
```
Поэтому:
```Python
loss = nn.CrossEntropyLoss()
```
и отдельно делать Softmax НЕ нужно.

## 4. `nn.BCEWithLogitsLoss`
!***Binary Cross Entropy, BCE***! (Бинарная кросс-энтропия) базовая функция потерь в машинном обучении для задач классификации с двумя возможными исходами

**Для:** бинарной классификации.
Примеры:
```
Спам / не спам
Кот / не кот
Болен / здоров
```
***Формула***

$$
L =
-\frac{1}{N}
\sum_{i=1}^{N}
\Big[
y_i \log(\sigma(x_i))
+
(1-y_i)\log(1-\sigma(x_i))
\Big]
$$
где:
$σ(x) — сигмоида (Sigmoid)$
Что делает внутри
```
Sigmoid
+
BCELoss
```
Поэтому сигмоиду вручную применять не нужно.
### 5. `nn.BCELoss`
***Формула***
$$
L =
-\frac{1}{N}
\sum_{i=1}^{N}
\Big[
y_i \log(x_i)
+
(1-y_i)\log(1-x_i)
\Big]
$$
Особенность
Ожидает вероятность:

```
0 ≤ x ≤ 1
```

На практике почти всегда используют:
```Python
nn.BCEWithLogitsLoss()
```

## torch.optim (оптимизация "начало обучения")
И SGD, и Adam решают одну задачу:
$w=w−step$
### SGD
**Стохастический градиентный спуск (SGD, Stochastic Gradient Descent)** - *это алгоритм оптимизации, который изменяет веса нейросети так чтобы уменьшить функцию потерь ([[Loss]]/Loss.md).*

$w_{new} = w_{old} - \eta \nabla L$

$w$ - веса модели
$η (eta)$ - learning rate
$∇L$ - градиент функции потерь

**Mini-batch SGD** - *это все тоже, что и свыше, но теперь мы берем батчи (небольшой размер): `32`, `64`, `128`....*
далее градиент loss(a) -> обновление весов

```Python
# На вход оптимизатору подаются параметры модели: model.parameters()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

`model.parameters()` - веса модели (где model объект на основе класса (нашего класса), созданного при наследование от `nn.Module`)

`lr` - learning rate
### **Adam** (Adaptive Moment Estimation)
Adam = SGD + “память + адаптация”
Adam - это оптимизатор, который сочетает:
- **momentum (память о направлении)**
- **адаптивный learning rate (масштабирование шага)**
- так же сам SGD
(я его часто использую)
### **2 функции оптимизатора**

`optimizer.step()` и `optimizer.zero_grad()`

`optimizer.step()` - эта функция обновляет параметры на основе градиентов, как написано выше. 

`optimizer.zero_grad()` - обнуляет все градиенты, это очень важная функция, если бы мы вызвали `backward` функцию для функции потерь, когда градиенты параметров не равны нулю после предыдущего пакета, новые градиенты фактически добавились бы к предыдущим, а не перезаписали бы их (а это уже сломает обучение).

> [!NOTE] ПЕРЕД КАЖДЫМ `backward`
> `optimizer.zero_grad()`
